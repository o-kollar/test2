Sprout

A data-first reactive templating language with exactly two attributes: data: declares state, bind: binds it to the DOM. The simplicity of Alpine.js, with the lazy, resumable interactivity model of Qwik.

Open the playground Read the directives

01. Overview

Paint immediately, wire up on first touch.

Declare state with data: and the template renders it immediately — no hydration, no JS execution required just to display values. Framework code (effects, event handlers) is only wired up for a component the first time the user actually interacts with it, so pages with hundreds of components stay cheap until they're touched.

  }"
>
  <button bind:click="dec">-</button>
  <strong bind:text="count"></strong>
  <button bind:click="inc">+</button>

  <input bind:value="name" />
  <p>Hello, <span bind:text="name"></span>!</p>
</div>

02. How it works

Every data: root goes through two phases.

1Paint

On load, data: is evaluated once and every bind:* in the subtree is rendered from it. No reactivity, no listeners: just the current values on screen.

2Resume

A delegated listener on document waits for any event a component cares about. The first one inside a root makes its data reactive and adopts the painted DOM in place, so the element you clicked or typed into is never replaced.

Event methods can also be async. While the promise runs, Sprout sets pending to true; the resolved value goes to data and a rejection to error. Sprout only writes the fields you declare in data:, and when calls overlap only the most recent result is kept.

03. Directives

Two attributes; the value's type decides the behavior.

data: declares state and bind:<name> binds it to the DOM. There's no bind:text/bind:show/bind:list to memorize — <name> is just a label (used verbatim as an attribute or event name where relevant); the type of the evaluated value decides what happens. The type is checked the first time the expression runs and stays fixed after that.

Value type Behavior
function Attach an event listener; <name> is the event name, e.g. bind:click="save". Non-bubbling events such as focus work too.
array Repeat this element once per item, exposing item/index; object items keep their identity automatically
boolean Toggle the <name> attribute: present when true, removed when false, e.g. bind:hidden="!open" or bind:disabled="busy". The element stays in the DOM.
object Class map: { className: boolean } merged into class; keys that disappear are removed
string / number / null Set textContent when <name> is text, otherwise set the <name> attribute

On input, select and textarea, the first bind:<name> is a two-way model that listens to both input and change. Any further bind:* on the same control follows the rules above, so bind:keydown="search" or bind:class work alongside the model. Attribute order doesn't matter for arrays: bind:class="{ done: item.done }" may come before the list binding it depends on.

04. Public API

Exposed on window.Sprout for dynamic markup and advanced use.

Sprout auto-mounts document on load, so most pages need none of this.

Method What it does
Sprout.mount(container) Paints every [data:] root in container (including container itself) and arms it to resume on first interaction. Roots that are already mounted are skipped, and one broken root doesn't stop the others.
Sprout.start() Equivalent to Sprout.mount(document); called automatically once when the page loads.
Sprout.reactive(object) Wraps an object in the same deep, memoized reactive proxy that backs every data: root. Useful for sharing state between a component and plain JS code.
Sprout.effect(fn) Runs fn immediately and re-runs it (batched in a microtask) whenever a reactive property it read changes. Every bind:* binding is built on this primitive.
Sprout.invoke(toolName, args, container) Resolves a (mocked) tool/AI call, validates the result as untrusted markup and mounts it into container (an element or selector). See AI tool invocation.

05. Limitations & trust model

What Sprout deliberately doesn't do.

Expressions are codeTreat templates like inline scripts ⌄

Author-written expressions run through Function() + with, not a sandboxed parser. Never mount markup built from untrusted strings with Sprout.mount, and expect a strict script-src CSP to need 'unsafe-eval'. As a safety net, bindings never set on*/srcdoc attributes or javascript: URLs.

Binding types are fixedDecided on the first run ⌄

A bind:<name> attribute's behavior is decided by its value's type the first time it runs — don't later turn a list into a string. One element can carry only one list binding; wrap it to nest lists.

Booleans toggle, never unmountNo conditional rendering ⌄

A boolean only adds or removes the <name> attribute. To show and hide content, toggle hidden with bind:hidden="!open"; hidden elements keep their DOM state and bindings. bind:text is the exception and renders "true"/"false".

What is reactivePlain objects and arrays ⌄

Plain objects and arrays are wrapped deeply and memoized, so push, splice, index writes, new keys and delete all trigger updates. Date, Map, Set and class instances are stored as-is; replace them to trigger an update. Inside a list, this in a method is the row's scope: item and index belong to the row, and every other property reads and writes through to the root data: object.

ListsIdentity-keyed, no animation ⌄

Rows are keyed by object identity (or index for primitive values). DOM nodes and their effects are reused, and only rows whose position changed are moved. There are no cross-list moves or transitions.

Handlers are referencesNever a call expression ⌄

Deciding a binding's type means evaluating it, and evaluating a call runs it. Write handlers as a method reference (bind:click="save") or a no-argument arrow function (bind:click="() => remove(item.id)").

ScopeA single-file learning project ⌄

No SSR, no router, no dev tooling. Reach for a real framework once the app outgrows a page or two.

06. AI tool invocation

Mount tool output without trusting it.

Sprout.invoke(toolName, args, container) is an optional helper for tool-calling flows: it asks a tool for markup (here, a mocked stand-in for a real AI call), validates it and mounts the result into container.

invoke.js 
await Sprout.invoke("greeting-card", { name: "Ada" }, document.getElementById("slot"));
  • data: must be JSON. It is parsed with JSON.parse, never evaluated, so tool output can't define functions.
  • bind:* may only be a property path (name, item.title) rooted in that JSON state, item/index, or one of the tool's actions — no calls, operators or globals.
  • Behavior comes from actions: trusted functions the page author registers with the tool, merged into the component's state.
  • Removed before mounting: scripts, frames, styles, forms, templates and non-HTML (SVG/MathML) elements; on*/style attributes; javascript:, vbscript: and data: URLs.
